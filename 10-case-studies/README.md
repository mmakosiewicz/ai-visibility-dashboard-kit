# Case studies

What happened when the spec met real reports. **Reading only.** There are no
question lists, brand files or plans here to run or build from, on purpose:
every build starts from the user's own Brand Radar report (see
[`../AGENTS.md`](../AGENTS.md)).

- [SEO tools](seo-tools.md): 194 questions, 16 cards. The set the spec was
  written on, and two mistakes it now guards against.
- [Payments](payments.md): 50 untagged questions, 7 cards. The same spec
  contradicting most of its own defaults, and why.
- **Step 0 on real sets:**
  - A payments report of 50 questions: the proposal put capture as the main
    number for 7 of 8 topics, the same conclusion the hand-built board reached.
    Fraud & disputes was the weak topic.
  - A dental clinic's set with five off-topic questions mixed in: the proposal
    split those out as *outside the market* (sources only) and corrected two
    questions the word rules got wrong ("dentist near me open saturday" asks for
    recommendations). With no answers loaded, every number read *can't measure
    yet*, which is the right state before a report is pulled.
  - A 66-question report for a cancer charity: only one topic was a real contest
    (the charity named in 72% of answers). The other 47 questions were medical
    information where AI recommends no one, so the number worth watching was how
    often the charity's site was a source (3–7%).
  - A brand no AI has heard of (53 feature questions): every metric counting the
    brand read *at zero*. That's correct for an experiment's starting point.
